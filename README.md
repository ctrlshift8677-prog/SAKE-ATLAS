# SAKE ATLAS｜清酒產地圖鑑

一本以「御朱印帳」為概念的清酒品飲圖鑑：每一款喝過的酒是一頁，每個縣是一枚收集到的印。

## 資料夾內容

| 位置 | 用途 |
| --- | --- |
| `dist/` | **已經建置好的完整網站**，整個資料夾上傳到主機即可 |
| `data/sake-master-*.xlsx` | **主要資料**：你的酒記試算表（酒款主資料、品飲紀錄） |
| `data/data.json` | 補充資料：規格來源網址、舊版心得與照片對應，試算表沒有的欄位會從這裡沿用 |
| `data/catalog-meta.json` | 更新日期 |
| `data/prefectures.geojson` | 地圖輪廓 |
| `static/` | 樣式（site.css）、互動（site.js）、照片、水墨背景、分享預覽圖 |
| `build.py` | 把資料轉成網站的程式 |
| `preview.html` | 單一檔案預覽版，雙擊就能在瀏覽器打開 |
| `docs/` | 設計說明（DESIGN.md）與產品設定（PRODUCT.md） |

## 網站有哪些頁面

- `/` 首頁：地圖與右頁（滑過縣名會換成該縣的紀錄並蓋上酒造朱印）、最近喝過的折帖、照片、依酒米／酒種／酒造的索引、特定名稱酒對照表
- `/sake/` 全部酒款：搜尋、篩選（區域、縣、酒種、酒米、有照片、有心得）、排序、酒帖與清單兩種顯示
- `/sake/S0001/` 每一款酒各自一頁（共 203 頁），有自己的網址與分享預覽
- `/pref/yamagata/` 每個縣一頁（共 39 頁），依酒造分組
- `/guide/` 入門：特定名稱酒分類表、精米步合米粒、常見用語
- `/about/` 關於

篩選條件會寫在網址上，例如 `/sake/?rice=雄町&photo=1`，可以直接分享給別人。

## 更新酒款後重新產生網站

1. 用 Excel 更新你的酒記試算表，存檔後放進 `data/` 資料夾（檔名不限，會自動使用最新的那一份）。
2. 第一次使用前安裝讀取 Excel 的套件（只要裝一次）：

```sh
pip install openpyxl
```

3. 在這個資料夾開終端機執行：

```sh
python3 build.py
```

（Windows 若沒有 `python3` 指令，改用 `python build.py`。）畫面會顯示「資料來源：○○.xlsx（207 款）」。

4. 把新的 `dist/` 整個上傳覆蓋；`preview.html` 也會同時更新。

### 試算表欄位在網站上的顯示

- **品飲紀錄**：每一列都會出現在該酒款頁；只有 ID、還沒填日期或地點的待填列不會顯示。
- **喜歡程度、再喝意願**：以 5 分刻度呈現。全部酒款頁可以「依喜歡程度」排序。
- **整瓶購入意願**：只留在試算表供自己參考，網站不顯示。
- **價格**：有填金額就會顯示；「價格公開」填「不公開」的不顯示。套餐會標成「套餐總價」。
- **精米步合**：0.35、35、「65%以下」、「非公開」都能讀；有數字的會出現米粒動畫，也能在全部酒款頁用「精米」篩選。
- **香氣標籤、口感標籤**：用頓號分隔，例如「紅蘋果、白桃」。認得的詞會放上香氣輪與品酒杯（「紅蘋果」歸到蘋果、「微氣泡」歸到氣泡感），不認得的會照原文顯示成標籤。
- **酒造年度、出荷年月、開瓶日期、開瓶後變化**：顯示在那一次的品飲紀錄裡。主資料的酒造年度與製造年月顯示為「批次」。
- **備註**：品飲紀錄的備註是給自己看的，不會顯示；主資料的備註會以小字顯示在酒款頁。

### 同一支酒喝了好幾次

- **酒款主資料只留一筆**（同一個酒款 ID）。每喝一次，就在「品飲紀錄」新增一列，酒款 ID 填同一個。
- 每一列各自記錄那一次的日期、單杯或整瓶、地點、容量、價格、心得、分數。
- 網站上，酒款頁的「這一杯」會顯示「喝過 N 次」和切換鈕（例如「2026.09 自宅・整瓶」、「2025.10 清酒共和國・單杯」），點哪一次，杯子就倒那一次的量；下方的品飲紀錄會依日期列出每一次。
- **照片**：酒款主照片一張，照舊放進 `photos/`，用酒名或酒款 ID 命名。某一次品飲另外拍的照片，在那一列的「品飲照片」欄填上檔名（例如 `十四代-龍落之子-自宅.jpg`），再把照片放進 `photos/`，就會出現在那一次的紀錄裡。

### 套餐與活動的價格

同一天、同一個地點、「價格說明」相同的套餐或活動紀錄，只要其中一筆填了金額，其他筆會自動共用。價格說明裡寫了杯數（例如「清酒Omakase套餐 8杯」），會另外顯示約每杯多少。

### 照片

最簡單的方式：把照片丟進 `photos/` 資料夾，檔名用酒名或酒款 ID 都可以（見上面「加照片」）。

`photos-pending/` 放的是還沒有對應酒款的照片（不會上傳到網站）。等那支酒加進試算表後，用它的酒款 ID 重新命名，移到 `static/images/` 即可。


把照片用酒款 ID 命名後放進 `static/images/`（例如 `S0031.jpg` 或 `S0031.webp`），重新建置就會自動對上，不用改試算表。品飲紀錄的「品飲照片」欄可以填同一資料夾裡的檔名或圖片網址，會顯示在那一次的紀錄裡。

## 不用再傳給我：自己更新網站

做一次設定之後，更新資料或照片只要在 GitHub 網頁上傳檔案，網站會在 1～2 分鐘內自動更新，電腦不用安裝任何東西。

**一次性設定（約 15 分鐘）**

1. 到 github.com 註冊帳號，建立一個新的 repository（例如 `sake-atlas`）。
2. 上傳專案檔案。GitHub 網頁一次最多只能傳 100 個檔案，請使用另外提供的 `sake-atlas-github.zip`，它已經分成兩批，照裡面「請先看我.txt」的步驟拖進去即可。（`dist/` 和 `preview.html` 不用傳，Netlify 會自己產生網站。）
3. 到 netlify.com 用 GitHub 帳號登入，選「Add new site → Import an existing project」，選剛剛的 repository。建置設定會自動讀取 `netlify.toml`，直接按部署即可。
4. 完成後會得到一個網址；之後也可以在 Netlify 綁定自己的網域。

（Cloudflare Pages 也可以：建置指令填 `pip install -r requirements.txt && python3 build.py`，輸出資料夾填 `dist`，環境變數加 `PYTHON_VERSION = 3.11`。）

**之後每次更新**

- **改資料**：在 GitHub 進入 `data/` 資料夾，上傳新的試算表（同檔名會直接覆蓋），按「Commit changes」。
- **加照片**：在 GitHub 進入 `photos/` 資料夾，上傳照片後按「Commit changes」。檔名可以用酒名（例如 `十四代-雪女神.jpg`），也可以用酒款 ID（例如 `S0004.jpg`）。建置時會自動對應酒款、裁成 3:4、壓縮成網頁格式。
- 對不上的照片會列在 Netlify 的建置紀錄裡（Deploys → 點最新一次 → 搜尋「照片」），改一下檔名重新上傳即可。

用自己電腦也一樣：照片放進 `photos/`、試算表放進 `data/`，執行 `python3 build.py`，畫面會顯示對上幾張，詳細列在 `photo-report.txt`。

## 在自己電腦預覽

最快的方式：直接用瀏覽器打開 `preview.html`（雙擊即可）。這是把整個網站打包成一個檔案的預覽版，所有頁面、篩選和地圖都能操作，也可以直接傳給朋友看。每次執行 `build.py` 都會一起更新它。

如果要用和正式上線完全相同的方式預覽：

```sh
cd dist
python3 -m http.server 8080
```

然後打開 http://localhost:8080 。直接雙擊 html 檔案會無法正常連結頁面。

## 部署前請設定

打開 `build.py`，最上方的 `SITE`：

- `url`：填正式網址（例如 `https://sake-atlas.tw`）。填了才會產生 `sitemap.xml`，分享到 LINE、Facebook 時預覽圖也才會正確顯示。
- `contact_email`：填了之後，「關於」頁會出現合作與品飲會的聯絡方式。

改完後重新執行 `python3 build.py`。

網站必須放在網域根目錄（例如 `https://example.com/`），或使用支援資料夾 index.html 的靜態主機（Netlify、Cloudflare Pages、GitHub Pages、Vercel 都可以）。

## 資料欄位

現有欄位不變。以下是**選填的新欄位**，填了就會自動顯示，沒填則完全不出現：

酒款層級（與 `brand`、`name` 同一層）：

| 欄位 | 範例 | 顯示位置 |
| --- | --- | --- |
| `aromaTags` | `["水梨", "白桃"]` | 香氣輪（通常不用填，會從心得自動辨認） |
| `sweetness` | `2`（1 辛口 到 5 甘口） | 酒款頁「飲用建議」的座標 |
| `body` | `4`（1 輕盈 到 5 濃郁） | 同上，需與 sweetness 一起填 |
| `servingTemps` | `["冷酒", "燗"]` | 建議溫度 |
| `pairing` | `["生魚片", "烤雞串"]` | 搭配 |

品飲紀錄層級（`tastings` 裡）：`notes`（心得）、`wouldBuyAgain`（`是`／`否`）、`aromaTags`、`palateTags`。

## 風味描述怎麼寫

直接在心得（`note` 或品飲紀錄的 `notes`）用平常的話寫就好，例如「紅蘋果香明顯，口感圓潤，尾段微苦」。建置時會自動找出風味詞，酒款頁就會出現：

- **香氣輪**：這支酒的香氣以朱色標在輪上，滑過任何一種香氣都會顯示說明。
- **利き猪口**：口感會畫成從上往下看的品酒杯（白瓷、杯底藍色蛇之目）。酒色依酒的特性：白濁、琥珀、粉紅、甘口偏暖、飽滿較濃、輕盈較淡；有酸度會泛起輕快的漣漪，圓潤的漣漪緩慢平順；有氣泡感會冒泡。滑過口感詞時，杯中的酒會盪一下。
- **心得裡的風味詞**：會加上朱色虛線，滑過或點一下就會就地顯示說明。
- 全部酒款頁會多一個「風味」篩選，酒款頁也會出現「風味相近的酒」。

會被辨認的詞列在 `build.py` 的 `AROMA`（香氣）與 `PALATE`（口感）。想新增香氣（例如「荔枝」），照同樣格式加一行，寫上說明就好。前面有「不、無、沒」的詞會自動略過（例如「不甜」）。

如果想直接指定，不靠自動辨認，可以在品飲紀錄加上 `aromaTags`、`palateTags`，例如 `"aromaTags": ["蘋果", "白花"]`。

## 目前資料可以補強的地方

補上之後，網站會自動多出更多內容：

- 50 款沒有填酒種：不會出現在特定名稱酒的對照表裡。
- 164 款沒有填精米步合：酒款頁不會出現米粒動畫。
- 品飲紀錄的「品飲紀錄」欄目前只有 1 筆。心得是讓讀者停留、也最能被搜尋到的內容，建議優先補齊。
- 十四代 萬虹、產土 神宴一農、產土 香子六農與七農、農口尚彥研究所 山廢這 5 款的心得，目前只存在 `data.json`（舊版資料），網站會沿用；建議也貼回試算表，之後就只需要維護一份。

## 法規提醒

頁尾已放上「禁止酒駕」「飲酒過量，有害健康」與未滿十八歲勿飲酒的提醒。日後若有店家合作或付費推薦，依《菸酒管理法》第 37 條，廣告或促銷內容的警語標示有面積規定，也不得鼓勵飲酒；網站本身不可加入任何線上訂購或購物車功能。實際做法建議先洽詢主管機關或律師。

## 各縣的水墨風景

首頁右頁與縣別頁背後的水墨畫在 `static/scenes/`，由 `tools/paint_scenes.py` 產生（需要 numpy 與 Pillow）。畫題寫在 `build.py` 的 `SCENE_CAPTION`。想改某個縣的構圖，修改 `paint_scenes.py` 裡 `SCENES` 對應的那一行，然後執行：

```sh
python3 tools/paint_scenes.py yamagata
```

## 字型

標題使用霞鶩文楷 TC（LXGW WenKai TC），內文使用 Noto Sans TC，皆由 Google Fonts 載入，不需另外上傳字型檔。
